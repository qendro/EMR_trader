# H0/H1 implementation record

H0 adds a small DAG CPPN query adapter and a fixed coordinate decoder. H1 adds
the persistent layered runtime for mixed-delay graphs and one hidden-population
role-block schema. This increment does not close M2: B0, H2 learning/comparisons,
W8's sequence environment, and integrated M2 performance gates remain open.

The four CPPN inputs are source-x, source-y, target-x, target-y. Its identity
head is squashed through tanh. Coordinates match the pinned MLP lattice, with
input/hidden/output y=-1/0/1. A virtual last input at constant one develops the
hidden bias; it is not an observation or a carried node. Output biases are zero,
hidden activation is tanh, output activation identity, and responses one.
Threshold equality expresses no edge. The transformation is
sign(q) × (abs(q)−threshold)/(1−threshold) × max_weight above the threshold.
Unknown options and nonfinite queries are rejected. Query slabs bound temporary
storage independently of genotype and phenotype capacities.

The decoder writes input-hidden and hidden-output immediate blocks, and a
separate delayed hidden-hidden block, directly. It never routes a large substrate
through the direct genome's 128-edge limit. Generic layered plans additionally
support several hidden layers and simultaneous immediate/delayed edges between
the same nodes. Delayed edges read the prior state, including prior inputs;
outputs otherwise reflect the current observation through immediate layers.

## 2026-11-10 calibration revision

Protocol v1 calibrated hidden preactivations in P=2/B=8 matrix products and froze
c=30 from CPU and RTX 3070. The first large audit checked stable trajectories
and random hidden preactivations but omitted the decoded output preactivation.
An explicit same-incoming-hidden output check then failed on the CPU's
1,024-node repeated-weight fixture. The failure is retained under
`h1-development/output-threshold-cpu/threshold-failure.json`; the initial audit
is incomplete evidence and cannot qualify H1.

The arithmetic remains FP32 with explicit HIGHEST operations. The observed
case exposes accumulation order for a single-candidate, two-output reduction;
it is not accepted by the batched-hidden calibration. Before new experiments,
`h1-contract-v2.json` adds single-candidate hidden products and eight declared
constant-term output fixtures, retaining positive/mixed/cancellation matrices.
The coefficient rule remains max(1, ceil(2×max(error/(2^-24×S)))) and uses only
CPU and RTX 3070. RTX 3060 only validates the frozen value.

Every earlier c-dependent result is superseded: both v1 calibration lanes,
RTX 3060's v1 validation, and the initial CPU 256/1,024-node audit. All are rerun
under v2 on their respective profiles. The small-fan-in and 128-step trajectory
tolerances are unchanged. No M2 acceptance run preceded this revision. This is
an empirical arithmetic envelope, not a worst-case bound or a claim about
arbitrary recurrent dynamics. Raw failures and both frozen coefficients remain
available for review.
