# S2 memory scheduling contracts

`rollout_memory_budget_bytes` is an optional manifest field. For each
execution signature and scenario count, the runner estimates plan, policy,
environment and temporary arrays, then selects the largest microbatch no
greater than the manifest ceiling that fits. It refuses a budget that cannot
hold one candidate. The chosen batch and estimate are recorded by namespace
in every generation's `rollout_schedules`. Semantic scenario keys and fitness
order are independent of microbatch size.

`phenotype_storage_budget_bytes` optionally limits converted adaptive plans.
The adapter estimates the compact and bucket-padded host storage from active
position counts before conversion, then checks the actual converted storage
before returning the population. A budget failure is an explicit overflow.
`discovery_microbatch` optionally invokes the pinned public EMR feedforward
query once and queries/builds recurrent connections in population slices.
This bounds the per-call recurrent pair-output tensor without changing the
native CPPN population or returning truncated graphs. It still retains the
full feedforward substrate and the final recurrent substrate fields for the
whole population. The storage budget does not include those native buffers
or the JAX compiler's workspace. They remain part of measured host/VRAM
peaks and the S2 resource gate; the schedule estimate is not a device
allocation guarantee.

Both limits are opt-in so existing frozen manifests retain their behavior.
The [development report](../benchmarks/S2-DEVELOPMENT-REPORT.md) records a
bounded smoke. W6 and W7 establish whether the limits work at scale.
