# A0 adaptive configuration boundary

The [Q2 decision](decisions.md) permits A0 work at depth 4, population 128,
with a 32,768-slot recurrent connection cap. The first
[A0 manifest](../configs/a0-adapter-v1.json) defines the CartPole interface.
`neuroevo.adapters.emr.translate` accepts that narrow semantic configuration
and the exact measured Q2 base manifest, then returns the public
`EMRHyperNEAT.create_config` input. `settings` rejects every unknown key,
invalid bound and unsupported mode before creating an upstream object.

| A0 option | Upstream setting or effect |
| --- | --- |
| Population, max depth | `population_size`, `emr_hyperneat.max_depth` |
| Variance and weight thresholds, max weight | Same named discovery fields |
| Input/output coordinates | `substrate.input_coords` and `output_coords` |
| Recurrent band threshold | `emr_hyperneat.band_threshold` |
| Recurrent connection capacity | `recurrence.max_sparse_conns`, with `sparse_cap_policy=refuse` fixed |
| Recurrent settling steps | Substrate and recurrence `activate_time` |
| Recurrent switch | Either the measured per-genome recurrence recipe or an explicitly disabled recurrence recipe |

CPPN operators, canonical variance behavior, standard execution, FP32, tanh
hidden units, sigmoid upstream outputs, and disabled dynamic functions, slot
cache and alternate aggregation stay pinned to Q2. The legacy
`recurrence.max_connections` field is an upstream no-op and is omitted from
the generated configuration; supplying it as an A0 option is rejected.
Streaming, offload, node-list, palettes, neuromodulation, locality, alternate
aggregation, and cache modes are likewise outside this versioned boundary.
Adding one requires a separate capability decision and test.

The pinned public lifecycle is `EMRHyperNEAT.create_config`, `initialize`,
`run_generation`, and `evaluate_on_data`. The population masks, weight blocks
and sparse recurrent edges currently observed in Q2 are private generation
caches. A1 will need a version-locked extraction seam or a minimal upstream
patch to expose the evaluated phenotype; A0 does not imply that a public
phenotype export API already exists.

The [adapter test](../tests/test_emr_adapter.py) checks that the pinned public
config API accepts the translated recipe, that each exposed numeric or
coordinate option changes the upstream interpreted state, that feedforward
recurrence is disabled, and that unsupported options fail. The test passes on
the Docker CPU profile. This completes the initial A0 configuration contract;
adaptive graph conversion, output parity and persistent rollout remain A1/A2.
