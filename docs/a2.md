# A2 adaptive evolution integration

`EMREvolution` uses the pinned EMR public `population_substrates(state)` API to
decode the current TensorNEAT population before scoring it. `extract_public`
converts every member into a compact layered block phenotype. The adapter
pads each generation to one bounded hidden width for the existing JAX rollout
evaluator, then associates the returned fitness with the exact asked genomes
and calls the native compiled TensorNEAT tell. It rejects stale/misordered
fitness, a changed population, unsupported function modes and capacity
overflow. This is genuine EMR discovery and native evolution; the task score
comes from the platform's persistent stateful rollout.

The shared runner now accepts `adapter.kind=adaptive-emr-v1`, validates its
task interface against the strict [A0 configuration](a0.md), and uses the
existing CartPole and memory evaluators, final-generation validation,
held-out selection, portable archive and native checkpoint flow. Its history
records every genome's active hidden count, input/output/recurrent edge counts
and weighted graph hash, along with decode, rollout and evolution times.
Export uses the compact phenotype, so padded execution slots do not appear in
portable champions. Upstream independent-sample settling is retained as the
[A1 reference](a1.md); the learning objective here uses one carried hidden
update per environment step and linear output logits for the platform actions.

The development smokes and immutable-image G9 pilots are summarized in the
[A2 development report](../benchmarks/A2-DEVELOPMENT-REPORT.md). The frozen
small-substrate [memory](../configs/a2-memory-acceptance-v1.json) and
[CartPole](../configs/a2-cartpole-acceptance-v1.json) manifests use depth 1,
population 128 and the shared five-seed task protocols. This scope measures
adaptive topology at the small comparison size. It does not establish a
depth-4 scale result.

A2 remains open until the five-seed acceptance cells, geometric diagnostic,
fixed-budget and fixed-time comparison reports, and end-to-end performance
gates are measured and audited. The second GPU also needs its required
validation cells. A one-seed smoke score is never an acceptance result.
